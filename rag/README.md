# ⚖️ Legal RAG System

A **research-grade Retrieval-Augmented Generation (RAG) pipeline** purpose-built for Indian legal documents. It combines hybrid retrieval, temporal validity filtering, IRAC-based reranking, and grounded LLM answer generation to answer complex legal queries with high accuracy and citation fidelity.

> This is the pipeline itself — CLI + evaluation only. For the web app
> (FastAPI backend + Next.js frontend that wrap this package), see the
> repo root [`../README.md`](../README.md), [`../backend`](../backend)
> and [`../frontend`](../frontend).

```
Query → Intent Classification → Query Expansion → Hybrid Retrieval (BM25 + Dense)
      → Temporal Filter → Hierarchy Structuring → IRAC Reranking → Grounded Answer
```

---

## ✨ Key Features

| Component | Description |
|---|---|
| **Multi-label Intent Classifier** | Classifies queries into `statute`, `case_law`, `definition`, `procedural`, `punitive` |
| **Hybrid Retriever** | Fuses BM25 sparse + BGE dense embeddings via Reciprocal Rank Fusion |
| **Temporal Validity Filter** | Filters out repealed/superseded legal sections based on effective dates |
| **Hierarchy-Aware Chunk Structurer** | Preserves parent-child relationships across Acts → Sections → Sub-sections |
| **IRAC Reranker** | Scores chunks using Issue, Rule, Application, Conclusion legal framework |
| **Grounded Answer Generator** | Produces answers with section-level citations using Gemini / Ollama |
| **Rocchio Query Expansion** | Pseudo-relevance feedback to expand sparse legal queries |
| **OCR Support** | Extracts text from scanned PDFs via Tesseract |
| **Case Document Pipeline** | Indexes FIRs, charge sheets, affidavits, and other legal documents |

## 🚀 Setup

### Prerequisites
- Python 3.10+
- [Ollama](https://ollama.com/) (for local LLM inference) — optional if using Gemini only
- Tesseract OCR binary (for PDF scanning support)

```bash
# Install Tesseract (Ubuntu/Debian)
sudo apt install tesseract-ocr

# Install Python dependencies
pip install -r requirements.txt
```

### Environment Variables

```bash
cp .env.example .env
```

Then edit `.env`:

```env
GEMINI_API_KEY=your_gemini_api_key_here   # Get free key at https://aistudio.google.com
```

Optional overrides (defaults are set in `config.py`):

```env
QDRANT_PATH=./qdrant_db
COLLECTION_NAME=legal_sections
EMBEDDING_MODEL=BAAI/bge-large-en-v1.5
CSV_PATH=./data/dataset.csv
JSON_PATH=./data/final_dataset.json
```

## ⚙️ Usage

### Step 1 — Prepare the Dataset

Place your `dataset.csv` in `data/`, then convert it to JSON:

```bash
python data/csv_to_json.py data/dataset.csv data/final_dataset.json
```

### Step 2 — Build BM25 Index

```bash
python data/build_bm25_idf.py
```

### Step 3 — Index into Qdrant (Vector DB)

```bash
python data/indexer.py data/final_dataset.json
```

### Step 4 — Run a Query

**One-shot CLI:**
```bash
python main.py "What is the punishment for hacking under IT Act?"
```

**Interactive CLI** (statutes + case documents, `/upload`, `/case`, `/graph`):
```bash
python legal_rag_system.py
```

**As an HTTP API** — this package has no server of its own; the FastAPI
service in [`../backend`](../backend) imports `legal_rag_system.LegalRAGSystem`
directly and exposes it over HTTP for [`../frontend`](../frontend). See
`../backend/README.md` to run it.

### Step 5 — Index Case Documents *(optional)*

```bash
python data/case_indexer.py /path/to/case_documents/
```

## 📊 Evaluation

Run the full evaluation suite against the benchmark:

```bash
# Full benchmark evaluation
python evaluation/evaluate.py evaluation/benchmark_scenarios.json

# Case document evaluation
python evaluation/evaluate_cases.py evaluation/benchmark_cases.json

# Diagnose retrieval recall failures
python evaluation/diagnose_recall.py

# Statistical significance tests
python evaluation/significance_test.py

# Run all evaluations at once
python run_all_evaluations.py
```

### Benchmark Format

`benchmark_scenarios.json` entries follow this schema:

```json
[
  {
    "query": "What is the punishment for hacking?",
    "gold_sections": ["ITA_066"],
    "gold_answer": "Hacking is punishable under Section 66 of the IT Act..."
  }
]
```

## 🔧 Configuration

All tunable parameters live in [`config.py`](config.py):

| Parameter | Default | Description |
|---|---|---|
| `EMBEDDING_MODEL` | `BAAI/bge-large-en-v1.5` | Sentence embedding model |
| `RERANKER_MODEL` | `BAAI/bge-reranker-large` | Cross-encoder reranker |
| `OLLAMA_FAST_MODEL` | `qwen2.5:3b` | Fast LLM for query expansion |
| `OLLAMA_ANSWER_MODEL` | `qwen2.5:14b` | LLM for answer generation |
| `BM25_TOP_K` | `25` | BM25 retrieval candidates |
| `DENSE_TOP_K` | `25` | Dense retrieval candidates |
| `FINAL_TOP_K` | `10` | Final chunks passed to the generator |
| `IRAC_WEIGHTS` | `{issue:0.30, rule:0.35, ...}` | IRAC scoring weights |

## 🧰 Tech Stack

| Layer | Technology |
|---|---|
| **Vector DB** | [Qdrant](https://qdrant.tech/) (local) |
| **Embeddings** | `BAAI/bge-large-en-v1.5` via `sentence-transformers` |
| **Reranker** | `BAAI/bge-reranker-large` |
| **LLM (cloud)** | Google Gemini via `google-genai` |
| **LLM (local)** | Ollama (`qwen2.5`) |
| **Sparse Retrieval** | BM25 via `rank-bm25` |
| **API Server** | FastAPI + Uvicorn (`../backend`) |
| **OCR** | PyMuPDF + Tesseract |
| **Evaluation** | ROUGE, NLTK, scikit-learn |
